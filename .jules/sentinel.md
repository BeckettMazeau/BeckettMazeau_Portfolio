## 2025-06-02 - [CRITICAL] Fix Cross-Site Scripting (XSS) via Attribute Injection
**Vulnerability:** The `esc(s)` function used to sanitize output before rendering it into the HTML structure dynamically did not escape double quotes (`"`) and single quotes (`'`). This meant user-controlled data placed within HTML attributes (e.g. `title` inside an `alt="..."` attribute) could break out of the string and execute arbitrary JavaScript using event handlers like `onerror` or `onload`.
**Learning:** Even though basic HTML characters like `<` and `>` were escaped, omitting quote escaping in an attribute context represents an XSS vulnerability, as modern applications heavily rely on strings appended straight into attributes (e.g. via `innerHTML`).
**Prevention:** Always escape double and single quotes (`&quot;`, `&#39;`) in addition to `<` and `>` when creating a manual string HTML escaping utility, especially if its outputs will be used inside HTML attributes.

## 2025-06-03 - [HIGH] Fix Cross-Site Scripting (XSS) via Unvalidated URL Schemes in Sanitizer
**Vulnerability:** The Python script (`redesign/build_site.py`) implements a custom HTML sanitizer (`Sanitizer` class) for JSON content. It explicitly allowed the `a` tag and its `href` attribute, but it failed to validate the URL scheme (e.g., `javascript:`, `data:`, `vbscript:`). This allowed persistent XSS where an attacker modifying the JSON content could inject malicious URIs that executed JavaScript on click.
**Learning:** Even when using an HTML parser to build a strict allow-list for tags and attributes, attributes that accept URLs (`href`, `src`, `action`) must additionally validate the scheme to prevent URI-based XSS attacks.
**Prevention:** Always validate URL schemes in HTML sanitizers. Ensure that potentially executable URI schemes (`javascript:`, `vbscript:`, `data:`) are rejected or that only a strict allow-list of schemes (`http:`, `https:`, `mailto:`, etc.) is permitted for any URI attribute.
